## 1. Метрики мониторинга

Для мониторинга MongoDB предлагается использовать Prometheus, MongoDB Exporter и Grafana.

| Метрика | Назначение |
|---|---|
| CPU Usage | Выявление перегруженных узлов |
| Memory Usage | Контроль потребления памяти |
| Disk I/O | Выявление высокой нагрузки на диски |
| Operations/sec | Количество операций чтения и записи на каждом шарде |
| Query Latency (p95/p99) | Выявление медленных запросов |
| Replication Lag | Контроль отставания Secondary от Primary |

## 2. Обнаружение горячих шардов

Для анализа нагрузки на каждый шард используются команды:

// Статистика операций и ресурсов
db.serverStatus();

// Состояние шардированного кластера
sh.status();

// Распределение данных по шардам
db.getSiblingDB("somedb").products.getShardDistribution();

// Статус балансировщика
sh.getBalancerState();
sh.isBalancerRunning();

serverStatus() выполняется непосредственно на узлах MongoDB, остальные проверки — через mongos.


## 3. Устранение дисбаланса

Автоматическая балансировка

Используем встроенный MongoDB Balancer, который автоматически перераспределяет диапазоны данных между шардами при превышении порогов дисбаланса.

// Включение балансировщика
sh.startBalancer();

// Проверка состояния
sh.getBalancerState();

// Проверка балансировки коллекции
sh.balancerCollectionStatus("somedb.products");


При существенном росте нагрузки возможно добавление новых шардов в кластер. Balancer будет постепенно перераспределять данные между ними.
