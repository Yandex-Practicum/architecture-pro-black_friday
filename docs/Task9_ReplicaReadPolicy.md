# Задание 9. Настройка чтения с реплик и консистентность

## Общий подход
Выбор read preference основан на допустимости eventual consistency для конкретной операции:
- **Secondary / secondaryPreferred** — когда пользователю можно не самые актуальные данные с отставанием в 1–5 секунд (каталог, история).
- **Primary** — когда задержка недопустима: списание остатков, оформление заказа, работа с активной корзиной.

---

## 1. Коллекция `products`

| Операция чтения                                        | Read Preference      | Обоснование                                                                                                        |
|--------------------------------------------------------|----------------------|--------------------------------------------------------------------------------------------------------------------|
| Просмотр каталога / фильтрация по категории            | `secondaryPreferred` | Пользователь увидит цену, актуальную на 1–3 секунды назад, цены и так могут меняться до момента оформления заказа. |
| Карточка товара (описание, базовая цена)               | `secondaryPreferred` | Данные меняются относительно редко.                                                                                |
| Чтение остатков (`stock`) при оформлении заказа        | `primary`            | Если прочитать устаревший остаток с secondary, можно продать товар, которого уже нет.                              |
| Чтение товаров при работе с заказом                    | `primary`            | Необходимо прочитать цену на момент заказа, иначе можно продать по цене, отличающейся от актуальной.               |
| Поиск товаров для админ-панели или дашбордов аналитики | `secondary`          | Аналитические запросы тяжёлые, не критичны к задержке.                                                             |

Допустимая задержка репликации для secondary: до 5 секунд.
Цены обновляются администраторами, не в реальном времени. Для каталога достаточно, чтобы данные были не старше нескольких секунд.

## 2. Коллекция `orders`

| Операция чтения                                            | Read Preference      | Обоснование                                                                                                                                     |
|------------------------------------------------------------|----------------------|-------------------------------------------------------------------------------------------------------------------------------------------------|
| История заказов пользователя                               | `secondaryPreferred` | Задержки при бизнес-процессах допускают получение устаревших на несколько секунд данных.                                                        |
| Просмотр статуса завершённого заказа                       | `secondaryPreferred` | Это статическая информация. Устаревание на несколько секунд не критично.                                                                        |
| Просмотр статуса активного заказа (только что оплаченного) | `primary`            | Пользователь только что нажал «оплатить» и ждёт подтверждения, необходимо получить как можно более новые данные, чтобы не заставлять его ждать. |
| Проверка статуса перед повторной отправкой уведомления     | `primary`            | Предотвращает повторную отправку.                                                                                                               |

Допустимая задержка репликации для secondary: либо до 1–3 секунд, либо дольше, но статусы заказов для недавно созданных заказов лучше читать с primary реплики.

## 3. Коллекция `carts`

| Операция чтения                                     | Read Preference  | Обоснование                                                                                                                          |
|-----------------------------------------------------|------------------|--------------------------------------------------------------------------------------------------------------------------------------|
| Получение активной корзины (`status: "active"`)     | `primary`        | Пользователь добавляет/удаляет товары. Чтение устаревшей корзины с secondary приведёт к потере добавленного товара или дублированию. |
| Слияние гостевой корзины в пользовательскую         | `primary`        | Нужна актуальная версия обеих корзин. Иначе можно потерять товары при слиянии.                                                       |
| Просмотр abandoned корзин для истории или аналитики | `secondary`      | Корзина уже неактивна.                                                                                                               |

Допустимая задержка репликации для secondary: до 1 секунды, но так как большинство операций читаются с основной реплики, то это менее критично.
